# GPT 生图自定义尺寸

## Goal

让普通聊天中的 `aiqq-gpt-image` skill 在结构化 `image_action` 中自主提供可选宽高：
AI 未决定尺寸时确定性使用 `1024x1024`，提供合法宽高时生成结果必须精确匹配该尺寸。
由于 GPT 图片接口只接受三种原生尺寸，应用选择最接近的原生比例请求，并在本地等比缩放、
白底补边到目标画布。

## Background

- 当前 `aiqq-gpt-image` 只定义 `mode`、`prompt` 和 `source_record_id`，聊天输出 Schema
  与领域 `ImageAction` 没有任意宽高契约。
- 当前工作区中的上一版实现让图片审核 AI 输出 `square`、`portrait`、`landscape` 或
  `null`，再映射到三个固定尺寸。用户已明确改为由生图 skill 的 `image_action` 提供可选
  自定义宽高，因此上一版方向映射不再是最终需求。
- 项目安装的 OpenAI SDK 将 Responses `image_generation.size` 限制为
  `1024x1024`、`1024x1536`、`1536x1024` 或 `auto`。`auto` 不能表达任意宽高，
  且会降低请求比例的确定性，本需求不使用它。
- 图片服务已经对上游结果做等比缩放和白底补边，可扩展为把原生结果规范化到独立的目标尺寸。
- QQ 上传边界对超过 2 MiB 的图片保留既有压缩、必要时缩小策略。本需求保证 GPT 图片服务
  输出的 JPEG 与元数据精确匹配目标尺寸，不改变 QQ 的公共上传安全策略。

## Requirements

### R1. Skill 和结构化输出

- `aiqq-gpt-image` 为 `image_action` 增加 `width`、`height`，两个字段在结构化 Schema 中
  必须存在，但允许同时为 JSON `null`。
- AI 应根据用户明确给出的分辨率、用途和构图决定宽高；没有可靠尺寸决定时必须把两项都设为
  `null`，不得为满足字段要求而编造任意值。
- 用户给出合法尺寸时按该尺寸输出；AI 自主选择时也必须遵守相同边界。
- 两项为 `null` 时使用 `1024x1024`。两项必须同时为整数或同时为 `null`。
- 整数单边范围为 `256..2048`，总像素不得超过 `4,194,304`。
- 缺字段、布尔值、浮点值、只提供一边、越界或超总像素都属于无效 AI 输出，沿用现有
  `InvalidAgentOutput` 路径，并且不得调用图片接口。

### R2. GPT 原生请求尺寸

- 对目标宽高的比例与 `1:1`、`2:3`、`3:2` 做对称、确定性的最近比例比较，分别选择
  `1024x1024`、`1024x1536` 或 `1536x1024`。
- 默认目标 `1024x1024` 必须请求 `1024x1024`。
- 生成和编辑必须使用同一个选择函数；502 重试期间复用第一次解析出的原生请求尺寸与目标尺寸。
- 不把任意 `宽x高` 传给上游，也不使用提供商 `auto`。

### R3. 工作流范围

- 普通聊天生成和引用图片编辑使用 `aiqq-gpt-image` 输出的宽高。
- 图片审核 AI 只继续负责安全性、有效性和 NovelAI 所需方向，不再覆盖 GPT `ImageAction`
  中的目标宽高。
- `/GPT生图` 不经过该 skill，也没有新增命令尺寸语法，因此继续使用默认 `1024x1024`。
- 直接构造未携带宽高的历史 `ImageAction(mode, prompt, source_record_id)` 保持兼容并使用默认值。
- NovelAI 的尺寸策略保持不变。

### R4. 输出尺寸与后处理

- Responses 适配器和保留的 Images API 适配器都必须区分“上游原生请求尺寸”和“本地目标尺寸”。
- 解码后继续使用 `ImageOps.contain` 等比缩放并在白色目标画布居中，不拉伸、不裁切主体。
- GPT 图片服务返回的 JPEG 实际像素和 `ImageAsset.width`、`height` 必须精确等于目标宽高。
- 保持现有 JPEG 质量、安全提示、参考图处理、错误分类、额度和仅 502 重试策略。
- 保持 QQ 上传层现有 2 MiB 保护；若其后续为平台交付而缩小图片，不视为 GPT 服务尺寸契约失败。

## Acceptance Criteria

- [x] Skill 和聊天 Schema 要求 `width`、`height` 存在且可同时为 `null`。
- [x] `null/null` 以及未携带宽高的兼容 `ImageAction` 请求并输出 `1024x1024`。
- [x] `1920x1080` 选择 `1536x1024` 上游请求，最终 JPEG 与元数据为 `1920x1080`。
- [x] `1080x1920` 选择 `1024x1536` 上游请求，最终 JPEG 与元数据为 `1080x1920`。
- [x] `800x800` 选择 `1024x1024` 上游请求，最终 JPEG 与元数据为 `800x800`。
- [x] 边界值 `256`、`2048` 和 4 MP 可预测校验；部分尺寸、错误类型、越界和超像素在网络请求前失败。
- [x] 普通聊天生成与编辑均保留 AI 输出宽高；图片审核不再改写它们。
- [x] `/GPT生图` 与旧 `ImageAction` 调用继续默认方图；NovelAI 回归行为不变。
- [x] 两个 GPT 适配器均覆盖原生尺寸选择、精确目标画布、实际 JPEG 像素和元数据。
- [x] 全部权威单元测试、编译检查和 diff 检查通过。

## Out of Scope

- 让 OpenAI 接口原生生成任意宽高。
- 使用 `size="auto"`。
- 为 `/GPT生图` 增加用户命令参数或解析提示词中的尺寸。
- 改变 NovelAI 尺寸选择。
- 改变 QQ 公共上传压缩、大小限制或重试策略。
- 服务重启、部署或真实付费生图。

## Risks and Deferred Validation

- 自定义尺寸通过本地缩放和补边实现，不会增加模型原生细节；接近 `2048x2048` 时可能放大
  1024 原图。
- 极端长宽比仍在单边和总像素限制内，但会产生明显白色补边，因为主体不得被裁切。
- GPT 服务输出保证精确尺寸；超过 2 MiB 时，后续 QQ 上传准备仍可能缩小图片以满足平台限制。
- 当前环境访问官方 OpenAI Docs 页面返回 HTTP 403；允许的尺寸枚举由项目锁定 SDK 的
  OpenAPI 生成类型确认。真实代理兼容性只在另行授权的线上验收中验证。
