# 设计 v4：完整存储 + Skill/读取脚本 + 完整历史 + Codex 看图

v4 实施设计。最近50条全文及完整字段、更早记录按需读取已由用户确认，现已授权实施。v1的强制“先输出image_read_action、再发起一次模型调用”不再是 Codex 的首选路径；Codex 首选同轮运行读取脚本并调用图片查看工具。替代 Responses 后端可继续使用结构化读取请求与图片输入作为兼容实现。

## 0. 存储扩展

按用户最新要求，存储方案保留群消息完整网关事件、每次消息版本、撤回/变更观测、图片链接与机器人图片元数据；用户最新明确取消图片原文件持久保存。详细设计见 [storage-design.md](storage-design.md)，作为下述读取链路的数据基础。事件日志与版本追加保存，group_messages保留当前视图，附件只保存URL/元数据及读取结果，不设图片原文件存储；旧数据明确标记legacy来源，不补造历史。

## 1. 已有图生图链路可以复用

详见 `image-edit-reference-flow.md`。复用 GroupMessageRepository 的同群定位、附件解析、WebImageService 下载、ImageAsset 和固定错误分类，不写另一套数据库解析或随意 curl。现有图片生成适配器继续只接收其选定参考图。

## 2. 每轮聊天输入：完整记录

完整的前后数据样例见 [input-comparison.md](input-comparison.md)，修改前由现有代码离线捕获、修改后为方案JSON。

从数据库整行映射构建可扩展JSON记录，不经固定字段DTO裁剪。当前15列全部保留，今后新增列自动保留；payload_json仅做JSON语义等价解析为payload，其他原列原值保留。payload所有未知键、任意原有嵌套、附件完整列表及null/false/0等值原样传递，不能按已知字段白名单过滤。遇解析失败或根类型异常，保留原payload_json与错误标记，禁止静默变成{}；字段名冲突须明确处理而非覆盖。派生role、has_image、引用索引、读取/视觉状态单独存放，不覆盖原始数据。详细筛选审计和契约见 [message-completeness-audit.md](message-completeness-audit.md)。

最近50条按数据库记录顺序选取并按时间顺序传入，不再调用正文/引用裁剪和空白折叠逻辑。与同群记录页的数据口径一致，包含用户、机器人、进度和撤回记录，原样标注event_type和recalled_at。撤回内容作为历史记录而非当前有效指令；图片读取服务仍不主动下载已撤回原图。当前请求作为独立完整记录，不因 before_message_id 查询排除而丢附件。外层规范字段与原始payload的自然重合可保留；避免额外生成冗余摘要反复复制正文，不能为了去重丢失原始字段。

附上上下文范围：选中条数、首尾记录/时间、有无更早记录、正文是否完整。旧 AIQQ_GROUP_HISTORY_MAX_CHARS 不再裁剪该聊天路径；实施时明确记录其弃用或适用范围，而不是填一个极大数字假装无限。对模型实际上下文超限给明确结果，不悄悄减少50条或截断字段。

附件 URL 会随用户要求的完整字段进入模型输入；带签名URL只用于本次读取，不抄入群回复或诊断日志。完整记录视为群聊参考数据，不允许其中的文本修改运行指令。

## 3. Skill 与两个脚本

计划新增 `.agents/skills/aiqq-chat-read/`，至少包含：

- `SKILL.md`：何时读图、怎样选择记录/附件、何时向前翻历史，以及必须实际查看像素才能描述图片。用户问历史图片时主动使用，不只建议重传。
- `scripts/read_image.py`：接收 record_id 和 attachment_index，向应用读取接口申请当前群的图片；按关联URL临时下载并验证后，将静态图片/采样帧写入本轮目录，输出路径、来源/帧映射和明确失败原因。
- `scripts/read_history.py`：接收记录编号或稳定游标、时间、发送者、关键词和页大小，查询当前群更早记录，返回完整字段、next_cursor 和 has_more。

示例为方案接口，文件尚未创建：

```text
python scripts/read_image.py --record-id 691 --attachment-index 0
python scripts/read_history.py --before-record-id 650 --limit 50
```

模型先调用脚本获得本地图片，再用 view_image 看图，然后回答。返回路径本身不算识图完成；已明确的当前附图也可直接使用 input_images，避免额外工具往返。图片读取和历史分页共用请求级预算，防止反复读取形成无限循环；建议每轮历史最多3页、每页50条，超过时说明检索范围并缩小条件。

完整 skill 目录（含脚本）必须复制到每轮工作区；现有只复制生图 SKILL.md 的方式需要扩展。依赖使用已知Python运行环境，不能假定临时目录自动导入AiQQ包。

## 4. 服务端读取接口与能力配置

脚本通过本轮绑定的本地读取接口访问应用；群范围由服务端回合上下文确定，不接收模型自行指定其他群、数据库路径或任意文件路径。采用短期回合凭据和只读方法，回合结束失效。接口返回当前群记录或处理后的图片；宿主程序负责按需下载，重用现有受限下载器；不在收到消息时后台下载或持久留存图片。可复用已有图片适配器的临时本地桥接生命周期模式，但不混用生图接口或凭据。

普通 ChatAgent 新增独立的读取能力配置，配套调整：

1. 开启当前CLI所需的脚本执行能力（shell_tool/unified_exec按实际版本验证），开启view_image。
2. 本轮图片文件输出需要写入临时目录，原read-only配置不足；为聊天读取回合配置限定目录的写入权限。
3. 脚本到本地读取接口需要网络/IPC通路；如使用SDK网络开关，要验证它实际开放范围。仅设network_access_enabled=True不能宣称只允许回环访问。图片公网下载仍由应用执行。
4. 修改BASE_INSTRUCTIONS，允许技能读取、指定脚本和图片查看；不再同时写禁止这些工具的指令。
5. 修改事件处理，按聊天能力允许command_execution及实测的view_image事件；不能只打开features后仍被ALLOWED_ITEM_TYPES中止。保留对其他模式的约束，不笼统放行全部未知事件。
6. 保留每轮临时工作区和结束清理，脚本取消/超时随请求收尾；工具进度只显示简短描述，不把命令、签名URL或本地路径发到群。

开启shell后，现有read-only/workspace-write及提示词不等于只能读取工作目录。实施前须用当前CLI支持的文件权限配置或独立进程隔离验证读取范围，避免脚本能直接旁路读取生产数据库、环境文件或其他群数据。若现有CLI不能做到，应在执行器层补足，不能靠skill文字承诺。该验证是技术接线的一部分，不新增用户审批流程。

能力仅作用于普通聊天读取回合；审核器和图片专用runtime使用各自配置。聊天的原生image_generation不因此开启，显式改图继续执行已验证的服务端工作流。

## 5. 按需临时读取、格式和错误

用户已明确不要保存图片原文件。本节改为按需临时读取：入库只保存完整附件URL和元数据，不新增图片缓存目录、image_blobs索引、后台预取队列或24小时/1GiB保留配置。

只有用户请求识图时，按消息/版本/附件选择关联URL，下载字节用于校验、解码和视觉输入。GIF/动态WebP可在本轮临时下载完整资源并有界抽帧，但不作为历史文件保存。建议每请求最多3个来源、每来源3帧、共9个视觉输入；原20MiB下载/解码限制与QQ发图2MiB压缩规则分别处理。

文件仅存在于本轮拥有的临时目录；实际图片输入或view_image读取完成前不能提前删除，整个请求成功/失败/取消后统一清理，异常退出留下的过期临时目录在启动时清理。相同请求可共享在途下载，不能据此建立跨请求持久缓存。临时资源需要并发和大小限制，但不设历史图片留存期限。

明确404/410或可信的链接过期响应时，提示“这张图片链接已过期或失效，请重新发送图片。”权限不足、超时和未知400等给对应说明，不冒称过期；无法继续读取时也可提示重新发送。原URL、附件信息和最近读取状态继续保留，不能将失败URL删成没有附件。

用户重新发图后建立新的消息/附件关联，不覆盖旧记录；模型依据新图回答。旧图不批量下载或补档。新发机器人图片从已有ImageAsset补齐元数据，现有QQ上传所需/media临时文件继续按现有机制工作，不新增用于历史识图的副本。

## 6. 后端兼容和有界执行

Codex为当前主后端：当前附图直接input_images，历史图由skill→脚本→view_image，更多历史由读取脚本返回。同一回合保留已查看来源状态，不把文件路径当作视觉证据。请求级图片/历史/耗时预算由应用接口执行，600秒前台转后台机制照旧。

Responses后端不具备Codex shell或skill装载，采用相同完整历史DTO和服务端读取操作，结构化读取请求后用input_image继续回答；控制调用/分页次数，禁止无终止条件的动作循环。当前消息、首轮50条和分页查询共用全记录序列化；两后端对可见字段、错误分类和输入图片数量保持一致；不自动更换配置模型。

## 7. 验证与发布

追加存储验收：原包原文/未知字段完整、重复/缺字段/冲突版本保存、真实可支持的撤回与乱序变更、机器人图片来源/交付元数据、投影失败重建不触发业务、临时文件清理、旧记录legacy迁移及保留新消息的回滚。详见storage-design.md第9节。

离线逐项核对50条完整序列化（包含总正文大于10000字符、换行、深层引用、超过20个附件、未知顶层列和payload键、空值及损坏JSON原文）、当前纯图片请求、稳定历史游标、跨群拒绝、skill/脚本实际装载、工具事件不中止、真实图片输入构造、临时文件和动画预算、取消与隔离清理。覆盖原GPT/NovelAI/QQ交付回归。

当前CLI的图片查看事件格式和网络/文件权限必须用不调用模型的本地测试确认；不能把历史配置名当作已经验证可用。实施获准后最多一次初始真实识图探针：两张文字只在像素里的测试卡，验证当前聊天模型读取两张；不生成图片、不代发QQ群消息。失败先查原因，不连续盲试。

待代码、独立审查和验证完成后，再按届时明确的部署范围操作；当前明确不改配置、不重启、不触发模型。记录精确源文件/配置备份和可回滚补丁，不覆盖已有未提交工作，数据库迁移保持追加式。
