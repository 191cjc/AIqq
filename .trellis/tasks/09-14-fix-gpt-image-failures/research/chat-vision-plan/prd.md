# 按需识图、完整聊天记录与存储：方案 v4

状态：2026-09-16，v4 已获“开始改动”授权并完成实现与部署，264项完整测试和真实两图识图验证通过。事件/版本/元数据存储保留，原图持久存储取消。最初 v1 保存在 `*-v1.md`，为废弃历史方案。

## 目标与已确认选择

机器人应能按需理解群图片和表情包，并依据完整的消息信息回答。用户已确认：

- 问到图片时才识别，日常接收图片不自动调用模型或回复。
- 接通 Codex 所需的图片查看、读取脚本等能力，使用 skill 指导读取。
- 每轮提供最近 50 条消息的全文和完整字段，取消这部分的 10000 字符裁剪；更早记录按需读取。
- 完整性以数据库整条记录和原始payload为准，已存未知字段也自动传递，不能再用固定字段清单限制；同群记录页中已有的进度和撤回记录保留其状态。
- 将已诊断的存储缺项纳入方案：完整群网关事件、消息历史版本、撤回/变更观测、图片链接与完整附件元数据、旧记录缺项标记。
- 图片原文件不持久保存，不接收即下载、不建立图片缓存；仅识图时临时下载并用完清理。确认链接过期/失效时提示用户重新发送。
- 原先“仅方案”阶段已结束，用户已授权开始改动；实施记录及实际验证结果见 execution.md、review.md 和结果文件。

## 范围与边界

“完整字段”指系统确实收到并存储的聊天记录信息，包括原始 payload；不等于服务环境变量或API凭据。“最近50条”指当前请求之前同群已保存的最近50条消息，包含用户、机器人、进度及撤回记录，明确标注类型和撤回状态；当前请求单独提供。不能把未被 QQ 网关送达的消息声称为已保存。

完整输入不得为了满足旧字符预算丢字段。若极端记录导致超过实际模型上下文，应明确失败或让用户缩小范围，不静默裁剪。更早记录按需查询，不一次导出整库；图片二进制走视觉通道，不塞入文字JSON。

包含技能脚本、能力配置、消息序列化、同群历史查询、原始事件与消息版本、撤回/变更观测、图片链接和完整元数据存储。持续自动识图、历史图片批量回填、任意执行群成员要求的系统维护命令、服务配置修改、切换模型、持久图片归档/缓存或恢复失效链接中的原图不属于该功能。

更多字段筛选、网页展示限制及入库前边界见 [message-completeness-audit.md](message-completeness-audit.md)。完整性验收不能止于当前已有15列，必须覆盖新列和未知嵌套字段。

存储结构、更新规则、建议保留策略和迁移验收见 [storage-design.md](storage-design.md)。事件/版本/附件元数据随消息历史保留；此前图片24小时/1GiB存储建议已取消，无图片原文件归档。

## 尚待验证的技术事项

当前 Codex CLI 的 view_image 事件格式、脚本运行权限配置和当前代理渠道视觉能力，需要在获准实施后以离线试验及有界真实识图验证。QQ群成员撤回/变更事件是否向当前账号推送、具体形状及权限需核对；当前SDK未找到相应群回调，不承诺获取平台未下发的信息。最新50条的极端输入需有明确容量错误。产品范围已确认；输入/工具及临时文件资源预算仍是方案参数，并未应用。
