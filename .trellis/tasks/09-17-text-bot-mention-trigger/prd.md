# 支持文本 @ 机器人触发

## Goal

让群成员误用普通文本输入 `@机器人名称` 时，只要它位于消息开头，也能像 QQ 原生提及
一样触发现有对话或命令流程。

## Background

- 当前机器人运行时显示名来自 `AiQQClient.on_ready()` 的 `self.robot.name`，当前线上名称为
  `浴火AI猫娘助手`，名称不可硬编码。
- `GROUP_MESSAGE_CREATE` 已经先保存完整事件，但仅在 `mentions[].is_you=true` 时继续分发；
  纯文本 `@浴火AI猫娘助手` 没有该结构化标记，因此当前不会触发。
- 原生提及的名称清理已经集中在群消息归一化边界，文本提及应复用同一分发和去前缀语义。

## Requirements

- R1：机器人就绪后保存当前运行时显示名；判断文本提及时使用该名称，不硬编码
  `浴火AI猫娘助手`。运行时名称不可用时沿用现有 `AiQQ` 回退名。
- R2：对于 `GROUP_MESSAGE_CREATE`，消息内容忽略前导空白后以完整的
  `@<当前机器人名称>` 开头时，视为触发机器人。名称比较严格区分大小写，不支持别名。
- R3：归一化时只移除开头匹配的一个文本提及和其后的空白，剩余内容进入现有命令、普通
  对话和附件流程。提及后没有文本时沿用现有“请告诉我需要处理的问题”行为；存在附件时
  沿用现有图片说明提示。
- R4：QQ 原生 `GROUP_AT_MESSAGE_CREATE` 和 `mentions[].is_you=true` 路径、消息持久化、
  去重、回复、延迟任务和权限行为保持不变。
- R5：不匹配完整当前名称、只在消息中部出现、或使用相似名称的普通消息继续只保存、不分发。
- R6：测试覆盖动态机器人名称、前导空白、无分隔符正文、仅文本提及、错误/中部名称、原生
  提及和普通非提及消息。

## Acceptance Criteria

- [x] `@浴火AI猫娘助手 你好` 和 `  @浴火AI猫娘助手你好` 均触发现有消息处理器，处理器收到
  的正文均为 `你好`。
- [x] 仅有 `@浴火AI猫娘助手` 时触发现有空问题回复；带图片时进入现有图片请求流程。
- [x] 机器人运行时名称变化后按新名称匹配，旧名称不再触发，代码中不硬编码线上名称。
- [x] `你好 @浴火AI猫娘助手`、`@浴火AI猫娘` 和普通消息不会触发。
- [x] QQ 原生提及仍正常触发并清理名称；同一事件不会重复进入工作流。
- [x] 相关 QQ handler/client 单元测试及全部权威单元测试通过。

## Out of Scope

- 支持机器人别名、旧名称、拼音、模糊匹配或不区分大小写匹配。
- 识别消息中部的文本提及，或改变私聊、主动消息及 QQ 回复行为。
- 修改机器人名称配置、命令语法或群消息数据库结构。
- 自动重启服务；实现完成后是否重启由用户另行决定。

## Risks and Deferred Items

- 文本提及没有 QQ 平台的结构化身份保证，因此只在消息开头做当前运行时名称的精确匹配，
  避免普通讨论机器人名称时误触发。
- 名称后的正文允许不带空格，以覆盖中文连续输入；这意味着以完整机器人名称开头的更长文本
  也会触发，这是满足手工输入习惯的有意选择。
