# AiQQ

一个使用腾讯 QQ 官方机器人 SDK 和 OpenAI Codex Python SDK 编写的群聊 AI 机器人。

## 1. 填写机器人凭据

复制环境变量模板：

```bash
cp .env.example .env
```

打开 `.env`，填写 QQ 开放平台提供的 `AppID` 和 `Secret`：

```dotenv
QQ_BOT_APPID=你的AppID
QQ_BOT_SECRET=你的Secret
AIQQ_QQ_HTTP_TIMEOUT_SECONDS=30
```

`AIQQ_QQ_HTTP_TIMEOUT_SECONDS` 控制 QQ 官方 SDK 的接口请求超时。图片文件较大时，
QQ 拉取临时图片可能超过 SDK 原先的 5 秒默认值，因此项目默认使用 30 秒；可配置范围为
5 到 120 秒。

项目支持 QQ 的群消息全量事件，并将收到的群消息保存到独立 SQLite 数据库：

```dotenv
AIQQ_GROUP_MESSAGE_DB=/var/lib/aiqq/group_messages.db
```

数据库按群与消息 ID 维护当前视图，并保存完整网关原文、外层字段、消息版本、附件链接与元数据。
网关事件先持久提交，再投影到消息视图；失败投影可在启动时恢复，不重放对话、生图或 QQ 发送。
同一消息的重复推送保留原始事件；缺失字段不抹掉先前信息，冲突版本可追溯。旧数据保留原有
记录编号和全部字段，以 `legacy_snapshot` 标记不能恢复的旧原包和版本。
机器人消息只在 QQ 确认成功并返回消息 ID 后进入当前视图；发送尝试另外保存开始、成功、失败或
取消状态及实际业务参数。机器人撤回自身消息或作画请求原消息都有确认事件；成员自行撤回/编辑没有已验证的平台事件时，
标记为未观测，不能认定消息从未撤回。数据库开启 WAL、权限为 0600，不自动删除历史。
机器人不会对未 @ 的消息自动回复。`GROUP_MESSAGE_CREATE` 中 `mentions.is_you` 与
`GROUP_AT_MESSAGE_CREATE` 共用按群与消息 ID 去重；原始事件入库后异步处理对话。

代码启用后，还需要每个群的管理员在机器人资料页开启“接收所有消息”。QQ 只会推送开启后
产生的新消息，不提供补拉此前历史消息的接口；管理员关闭后也会立即停止全量推送。

管理员消息查看页位于 `https://www.firesoul.cn/aiqq/group-messages`，使用浏览器 Basic Auth 验证。
用户名和口令只配置在服务器 `.env` 中，不得提交到 Git：

```dotenv
AIQQ_GROUP_MESSAGE_VIEW_USERNAME=admin
AIQQ_GROUP_MESSAGE_VIEW_PASSWORD=请设置独立高强度口令
```

页面按最近消息时间列出各群组，每页显示 50 条消息，并支持继续查看更早记录。附件图片和
引用消息会在页面中展示；完整事件中的鉴权令牌等原始字段不会直接输出到页面。
选择群组后，页面底部提供主动消息输入框；发送操作继续使用查看页的 Basic Auth，并额外
校验页面内的 CSRF 令牌。成功发送的消息会写入同一群消息数据库。

每条通过输入审核的 @ 请求会提供本群当前消息之前最近 10 条精简记录，以及独立的当前消息。
模型输入协议为 v4：记录固定包含编号、角色、发送者名称、时间、正文、消息类型、引用摘要、
图片标记与图片附件序号、撤回状态和进度状态；不会附带数据库行、原始 `payload`、网关事件、
附件 URL 或交付尝试。当前请求正文只出现在 `current_message.content` 一处。进度消息与撤回记录
仍带状态传入，正文不按字符预算裁剪。原来的 `AIQQ_GROUP_HISTORY_MAX_CHARS` 仍可解析，但不再
控制此聊天路径。超过模型真实容量时会明确说明容量不足。完整记录继续保存在 SQLite 中，供
管理页面和显式诊断查询使用；群聊记录始终视为不可信参考资料。

普通聊天自动装载项目内 `aiqq-chat-read` skill 及两个入口脚本：

- `scripts/read_history.py`：按编号、时间、发送者、关键词查询同群更早消息，稳定游标分页，
  每轮最多 3 个不同查询页、每页 50 条；默认返回上述精简语义记录，`--raw`、`--versions`
  或 `--events` 才返回完整诊断记录。等价查询复用同一页且不重复计入预算。查询结果由服务端
  只加入下一次模型请求，后续请求不重复追加；命令输出只显示页码/游标回执。
- `scripts/read_image.py`：按记录、附件序号和可选版本读取图片，返回本轮临时图片路径及来源信息。
  Codex 随后必须调用 `view_image` 查看真实像素，不能只凭 URL 或路径描述内容。

只在用户问到图片/表情时读取；纯图片 @ 请求可以直接识别。JPEG/PNG/WebP 可读，GIF/动态
WebP 最多抽 3 帧并注明采样；每轮最多 3 个来源、9 帧。收到消息不预下载，不持久保存原图，
只保存 URL、附件元数据和读取状态。读取结束、失败或取消后删除临时文件，启动时清理失去所属
进程的临时目录。既有 `/media` QQ 交付临时文件继续使用原有生命周期。

链接返回 404/410 时提示“这张图片链接已过期或失效，请重新发送图片。”权限不足、超时、
未知 400 和无效格式分别说明，不按链接年龄猜测过期。已撤回记录不会主动下载原图，纯系统
表情只依据实际名称/文字解释，不从 `faceId` 编造图片内容。

图生图继续由模型输出 `image_action.source_record_id`，服务端在同群查找并即时下载参考图，
审核通过后交给独立的 Images API 图片服务。当前附图、引用附件和历史查询找到的图片都可以
作为候选；引用关系不明或多图歧义时需要指定记录。读取图片不占生图额度。

继续在 `.env` 中填写 AI 接口配置：

```dotenv
OPENAI_API_KEY=你的代理服务SK
OPENAI_BASE_URL=https://api.airoo.cc/v1
OPENAI_MODEL=gpt-5.6-sol
OPENAI_TIMEOUT_SECONDS=280
OPENAI_MAX_OUTPUT_TOKENS=1000
AIQQ_AI_TOTAL_TIMEOUT_SECONDS=290
AIQQ_AI_BACKEND=codex_sdk
AIQQ_CODEX_CLI=
AIQQ_CODEX_RUNTIME_DIR=/var/lib/aiqq/codex-runtime
AIQQ_CODEX_WORK_DIR=/var/lib/aiqq/codex-work
AIQQ_CODEX_REASONING_EFFORT=high
AIQQ_CODEX_UTILITY_REASONING_EFFORT=high
AIQQ_GPT_IMAGE_SKILL_ENABLED=true
```

GPT 文生图默认复用上述密钥和代理域名，也可以独立配置：

```dotenv
OPENAI_IMAGE_API_KEY=
OPENAI_IMAGE_BASE_URL=
OPENAI_IMAGE_MODEL=gpt-image-2.5-flare
OPENAI_IMAGE_TIMEOUT_SECONDS=240
OPENAI_IMAGE_DOWNLOAD_TIMEOUT_SECONDS=60
AIQQ_IMAGE_USER_DAILY_LIMIT=100
```

`OPENAI_IMAGE_API_KEY` 和 `OPENAI_IMAGE_BASE_URL` 留空时分别复用
`OPENAI_API_KEY` 和 `OPENAI_BASE_URL`。图片服务直接调用 Images API，
文生图使用 `/images/generations`，参考图编辑使用 `/images/edits`，模型由
`OPENAI_IMAGE_MODEL` 指定，默认为 `gpt-image-2.5-flare`。请求显式指定
`response_format=b64_json` 和 `size=auto`，收到图片后校验并原样展示。图片调用不使用对话驱动模型；
旧的 `OPENAI_IMAGE_DRIVER_MODEL` 只保留解析兼容，不影响当前生图通道。

`OPENAI_API_KEY` 必须由你使用的代理服务提供。普通对话、内容审核和 NovelAI 提示词生成默认
通过 `openai-codex-sdk` 调用。SDK 每轮启动一次 `codex exec --experimental-json`，项目为代理
注册独立的 Responses provider，固定关闭 WebSocket 并使用 HTTPS 流。它不会读取管理员
`~/.codex` 中的账号、配置或个人 skill。

每个 AI 逻辑回合结束时会写入一条 `event=ai_turn_finished` 指标，包含随机请求编号、用途、
后端、模型、输入字节、耗时、状态、可获得的 token 用量与工具/历史/图片请求计数，不记录
提示词、群消息、签名 URL、业务标识或密钥。`OPENAI_MAX_OUTPUT_TOKENS` 直接限制 Responses
请求，也限制 Codex 聊天桥转发的 Responses 请求；当前 Codex SDK 的直接回合没有受支持的
硬输出上限，指标会明确记录 `output_limit_mode=unsupported_direct_sdk`。

普通对话、输入审核、图片提示词审核和 NovelAI 提示词生成每轮都创建独立临时 thread、
`CODEX_HOME` 和工作目录，结束后清理，不恢复以前的模型线程。审核和图片专用回合保留各自的
工具限制；普通聊天单独开启脚本执行与 `view_image`，并将整个读取 skill 目录复制进工作区。
聊天工具通过随机回合凭据访问服务端绑定的群历史接口，不能指定其他群或数据库路径。

普通聊天的 CLI 和所有工具子进程使用 Linux Landlock ABI 4 及 libseccomp 限制文件访问：
仅允许系统运行文件与本轮工作目录，禁止读取生产数据库、环境文件、其他回合和 `/proc`。
真实模型密钥由服务端临时桥持有，CLI 只得到回合令牌。TCP 限定本轮桥端口，UDP、新建 UNIX
套接字与跨进程读取/信号受到限制；Landlock 限制的是端口，**不是仅回环地址**。
隔离能力不可用时聊天失败，不退回不受限 shell。普通聊天仍可按配置使用原生网页搜索，
不能调用原生 `image_generation`。备用 Responses 后端用有界函数调用及 `input_image` 实现
相同的历史/图片读取，无 shell。所有允许的多图输入都会保留，不再静默只取第一张。
普通联网对话还可按需执行一次精准图片检索。Codex 必须根据用户要求、结果标题和图片说明，
在最终回答中按用户要求的数量和内容明确选定直接图片 URL，每次最多 5 张；要求超过 5 张时
返回最多 5 张并说明上限，未指定数量时按实际需要选择。程序不会按搜索顺序盲选，重复 URL
只发送一次。后续对话要求“发这张”时，模型只能根据本轮群历史参考资料识别此前选定的图片 URL。
每张图片都通过公网地址、真实格式、文件大小和像素校验后，按选择顺序放在最终文字之后逐张发送。
部分图片下载失败时仍发送其余成功图片并说明情况；全部失败时保留文字回答。
Codex 没有选图或无法确认匹配时只发送文字。找图只是下载公开搜索结果，不调用生图服务、
不占用每日生图额度，也不受全局生图锁限制。可通过 `AIQQ_WEB_IMAGE_SEARCH_ENABLED=false`
关闭；选定图片并发下载，每张下载时限由 `AIQQ_WEB_IMAGE_TIMEOUT_SECONDS` 控制，默认 20 秒。
模型完成一轮搜索时，会先发送
一句 40 字以内的阶段说明；阶段说明使用普通 Markdown，不带按钮，最多发送 4 次。正常 AI
对话会在同一次模型回答中同时生成完整正文和一条 50 字以内的直接摘要，不再额外请求摘要。
回复缩写缺失或失败时，程序会在本地生成不超过 50 字的回退文本。所有回复均使用普通
Markdown，不再自动添加 `text` 代码块包装。

普通对话中的上下文生图默认由 `AIQQ_GPT_IMAGE_SKILL_ENABLED=true` 开启。SDK 会为普通聊天
显式加载项目内的 `$aiqq-gpt-image` skill，把“按刚才那张的风格”等上下文指代整理成严格的
`image_action`；skill 不持有密钥，也不调用原生生图工具。实际生成复用 `/GPT生图` 的项目级
Images API 图片客户端，因此使用 `OPENAI_IMAGE_API_KEY`、
`OPENAI_IMAGE_BASE_URL` 和 `OPENAI_IMAGE_MODEL`。
`image_action` 的 `width`、`height` 均设为 `null`，文生图和改图统一使用 `size=auto`。
用户提出的尺寸、比例或保留构图要求写入提示词，由图片服务决定实际返回尺寸；程序不因尺寸
不同拒绝结果，也不保证与参考图尺寸一致。旧的合法宽高字段保留解析兼容，但不覆盖自动模式。
程序校验图片文件后保留返回的原始字节、格式、尺寸、透明度和元数据，不转换、压缩、缩放、裁剪或补白。
最多发送一张，并在最终文字之后通过
QQ 富媒体接口发送。“图呢”“重做”或
“按刚才的改成……”等续接请求只能使用本轮提供的当前群历史参考资料，普通图片咨询不会
触发生图。
统一输入审核会在同一次请求中判断普通文生图与参考图生图；参考图生图只以用户指定的当前群
消息图片记录为准，通过 `/images/edits` 上传参考图执行，并使用高保真输入模式。没有唯一匹配
的图片记录、图片附件已经过期或图片下载校验失败时不会开始生图，也不会占用当日额度。

原图读取失败会显示具体原因和处理建议，群内摘要与完整回答使用相同文案：

| 原因 | 回复示例 |
| --- | --- |
| 原图链接返回 404/410 | 引用的图片已过期或已失效，请重新发送原图后再试。 |
| 没有可用的原图记录/附件 | 未找到可用的原图，请重新发送图片后再试。 |
| 读取超时 | 读取原图超时，请稍后重试，或重新发送图片。 |
| 原图访问受限 | 无法访问原图，请重新发送图片后再试。 |
| 内容不是有效图片 | 原图无法读取，请重新发送有效的图片后再试。 |
| 超过原图下载大小限制 | 原图过大，读取失败，请压缩后重新发送。 |
| 其他下载失败 | 原图下载失败，请稍后重试，或重新发送图片。 |

有多个原图候选地址时，程序继续尝试其余地址；全部失败且原因一致才显示对应原因，
混合错误使用下载失败提示。原图链接的 404/410 与生图接口的 404 分开处理；网络故障
不会被判定为图片过期，接口原始错误和地址不会直接显示给群用户。

`OPENAI_TIMEOUT_SECONDS` 默认 280 秒。使用 Codex SDK 时它是慢回合与前台等待阈值，
不再是中止任务的硬超时；程序同时参考 `AIQQ_AI_TOTAL_TIMEOUT_SECONDS`，取两者较小值作为
群聊前台等待时间。达到阈值后机器人会发送“任务处理时间过长，后续进展请看这里”和随机链接，
Codex 任务继续在后台执行，检索进展与最终完整回答会更新到同一个临时文件。进展页面每 3 秒
自动刷新，完成后停止刷新；任务完成时也会 @ 原用户发送最终回复及图片。显式取消或服务关闭仍会终止相应 SDK 回合。
原文超过 50 字的文本回复会附带“查看完整输出”按钮，打开一个随机 HTTPS 临时页面；
页面采用适合手机和桌面阅读的排版，支持浅色和深色模式，并安全解析标题、列表、
代码块、引用、表格和链接。每个代码块顶部都有独立的“复制”按钮，只复制该段代码，
保留缩进和换行；无法自动复制时会选中对应代码，方便使用系统复制。页面不提供全文复制按钮。
完整原文默认保留 1 小时，链接过期后返回 404。普通对话、NovelAI 提示词方案、
修改结果、拦截原因和其他命令说明均采用相同的 50 字摘要规则。`AIQQ_MAX_REPLY_CHARS`
只保留给其他可能需要分段的内部流程，不控制群内文本摘要。

普通 AI 对话的最终群聊回复会在摘要正文前 @ 原用户，但不携带 `message_reference`，
以避免电脑 QQ 重复渲染回复内容。联网搜索阶段消息不 @，避免重复提醒。50 字以内的原文
不生成临时页面，也不显示查看按钮。

如果 QQ 明确返回“msgid已经过期,不能回复”（`40034031`）或
“回复消息msg_id已过期”（`40034005`），对话回复会去掉过期的被动回复上下文，
改为主动群消息补发一次。文字回复保留 @ 原用户；图片消息只发送图片，不附带 @ 或其他文字。
图片补发复用已经上传的媒体，不重复生图或上传。其他错误不会触发这次补发。
主动消息仍受 QQ 的发送权限和频次额度约束；被拒绝时记录发送失败，不循环重试。
前台对话最终回复发送失败会记录 `group_reply_delivery_failed`，不会重新生图，也不会
让这次发送异常逃逸到网关回调。600 秒前台等待不会延长 QQ 的 5 分钟被动回复窗口。
图片会先按 2 MiB 上限检查、压缩并保存到临时媒体目录，再尝试群内发送，因此文字发送
失败不会直接丢弃图片；保存时长仍由 `AIQQ_MEDIA_TTL_SECONDS` 控制。管理员指定回复和
检索进度消息不自动转为主动发送。

NovelAI 使用项目自带的 MCP 客户端，不依赖 Codex skill。在 `.env` 中填写：

```dotenv
NOVELAI_MCP_URL=https://你的MCP地址
NOVELAI_MCP_TOKEN=你的MCP访问令牌
AIQQ_PUBLIC_BASE_URL=https://你的域名/aiqq
```

也可以不直接填写 Token，改用 `NOVELAI_MCP_TOKEN_FILE` 指向服务器上的私密凭据文件。

迁移旧版时需要显式填写上述地址和 Token/凭据文件位置；新版不会自动使用旧版内置的
MCP 地址或 `~/.config/novelai-mcp/token`。凭据文件权限须为 `0600`。缺少配置时回复
“NovelAI 生图服务未配置，请联系管理员。”；连接未就绪时回复
“NovelAI 生图服务连接未就绪，请稍后再试。”。
`/health` 的 `novelai` 字段报告 `configured` 和 `ready`，启动日志也记录就绪状态；
只有发现远端 `generate_image` 工具后才会就绪。健康查询不会调用生图，原有 QQ/数据库
健康状态码规则保持不变。

Nai v5 作图使用独立的 [NovelAI Image MCP](https://xinvxueyuan.github.io/NovelAI-Image-MCP/zh/)
部署和 Bearer Token。在 `.env` 中设置：

```dotenv
NAI_V5_MCP_URL=https://www.fsstudy.com.cn/novel-ai-v5
NAI_V5_MCP_TOKEN=你的独立访问令牌
AIQQ_NAI_V5_DAILY_LIMIT=10
AIQQ_NAI_V5_WHITELIST=成员openid一,成员openid二
```

也可用 `NAI_V5_MCP_TOKEN_FILE` 指向权限为 `0600` 的私密凭据文件，不要同时填写明文 Token。
未配置 Token 时 `/health` 的 `nai_v5.configured` 为 `false`；启动时会检查新服务的
`generate_image` 工具，成功后 `nai_v5.ready` 才为 `true`。鉴权失败不会影响原 NovelAI。
`AIQQ_NAI_V5_WHITELIST` 可留空；填写 QQ 提供的 `member_openid`，不要填写昵称或群号。
Nai v5 成功次数按成员跨群累计，每天最多 10 张（可调整上限）。普通用户的成功次数也计入
原有共享额度；白名单成员使用 Nai v5 不受两层每日额度限制，也不占用共享额度，
但仍受全局单任务锁约束。失败或审核拒绝不计数。新计数表从功能启用后开始记录。

不要把 `.env` 文件发送给其他人或提交到 Git。


## 3. 启动机器人

```bash
source .venv/bin/activate
python -m aiqq.main
```

出现 `AiQQ 已登录` 后，保持终端和程序运行。在 QQ 群中发送
`@机器人 你的问题`，问题会被转发给 GPT，模型文本随后回复到群里。

管理员也可以在机器人服务器上主动向指定群发送一条文本消息：

```bash
uv run python3 scripts/send_group_message.py \
  --group <GROUP_OPENID> \
  --text '消息内容'
```

脚本只访问本机管理接口，并读取 `AIQQ_ADMIN_TOKEN` 或权限为 `0600` 的
`AIQQ_ADMIN_TOKEN_FILE`。默认发送 QQ 主动群消息，会占用平台的主动消息频次；指定
`--reply-to <MESSAGE_ID>` 时改为回复该群最近 5 分钟内的对应 @ 消息。

默认角色是中文 AI 猫娘女仆助手，会称呼当前对话用户为“主人”，回复自然带“喵”，
正文不使用 QQ 表情或 Emoji，需要表达情绪时可以使用纯文本颜文字。用户不能通过聊天改变
角色、称呼、性格或表达方式；此类输入会在进入正常对话前被拒绝。部署管理员仍可通过
`OPENAI_SYSTEM_PROMPT` 覆盖设定。
每条普通对话都会先进行独立的输入审核；成人内容命中时机器人只返回警告，不调用正常
对话、不联网。审核服务异常时按安全优先拒绝请求。
一条消息可以同时提出多个独立问题或任务，不会仅因问题数量被拦截，
也不会仅因多问题被归类为范围过大。普通批量查询、比较、排名和汇总不设检索目标数量上限，
不会仅因对象多、需要多次检索或逐项核实而拦截，例如七名角色的能力排名、九个章节的更新时间查询。
如果单个问题的范围仍明显过大，包含大量无法在一次群聊回答中可靠完成的阶段或交付物，
审核会请用户先拆成更小的问题。专业问题、深入推理、代码排错和联网查询不会仅因难度被拒绝。

普通对话默认提供 Codex 的原生网页搜索工具。模型会在用户明确
要求联网、问题涉及最新信息或需要核实时自行搜索，并在回答中保留来源链接；
不需要最新资料的普通问题不会强制搜索。设置
`AIQQ_WEB_SEARCH_ENABLED=false` 可以关闭此能力。内容审核和群聊回复缩写不会
使用联网工具。

机器人只处理群聊中明确 @ 它的消息；未 @ 的群消息只写入群消息数据库，用作后续对话的
参考资料，不会触发回复。每轮普通对话都使用新的临时 Codex thread，不保存跨轮模型会话；
需要延续的话题由当前群的近期消息提供上下文。
输入或图片提示词被审核拒绝时，回复会直接说明主要原因；若完整说明和安全建议过长，群聊
消息会先显示简短理由，并提供查看完整输出的入口。审核服务故障仍单独提示，不冒充内容拒绝。
QQ 正常 @ 的不同消息表示形式（包括服务端收到的 `[@机器人名称]`）都会在指令解析前
统一处理；原始聊天记录保持不变，用户按正常方式 @ 机器人即可。

机器人每次上线时会自动同步群聊指令面板。在 QQ 群中打开机器人的指令面板，可以使用
“菜单”“NovelAI提示词”“NovelAI生图”“Nai v5 作图”“NovelAI画风”和“Nai v5 画风”六个指令。

普通文本回复下方附带“功能菜单”按钮；原文超过 50 字时，再增加“查看完整输出”按钮。
点击“功能菜单”会自动执行 `/菜单`，随后显示“NovelAI提示词”“NovelAI生图”“Nai v5 作图”“NovelAI画风”和“Nai v5 画风”按钮；
也可以直接发送 `@机器人 /菜单` 打开该列表。这五个具体功能按钮只填充输入框，不会自动发送。
NovelAI 提示词方案会保留原有的三个“使用方案”和
“修改提示词”按钮，原文超过 50 字时在最后一行增加“查看完整输出”。

## GPT 文生图

GPT 生图只保留直接文本命令入口，可发送带斜线或不带斜线的命令：

```text
@机器人 /GPT生图 雨夜霓虹街道上的白猫，电影感光影
```

GPT 生图支持中文自然语言。对未在作图审核白名单中的账号，项目会通过一次独立的临时 Codex thread，同时审核成人内容和
画面有效性；审核服务异常时按安全优先拒绝，通过后再调用
Images API。审核不通过时会显示绿色标识的“使用建议”按钮，点击后把安全建议填入新的
GPT 生图命令。直接命令、普通聊天生图和参考图编辑均使用自动尺寸模式 `size=auto`。
模型默认为 `gpt-image-2.5-flare`，质量为高，输出单张图片，并额外加入 SFW 安全约束。
不指定输出格式或压缩质量；接口返回的有效图片按原始字节、格式和实际尺寸展示。
程序不因尺寸与参考图或提示词要求不同而拒绝结果，也不在本地转换、压缩、缩放、裁剪或补白。管理员可通过
`OPENAI_IMAGE_MODEL` 更换代理实际支持的图片模型。直接命令只接受画面描述，不能传入模型、
质量或其他底层生成参数。

图片服务通过 OpenAI SDK 直接访问配置的 `/images/generations` 或 `/images/edits`，
使用图片专用密钥，SDK 自身重试关闭。请求显式指定 `response_format=b64_json`；
程序要求响应包含可解码的 Base64 图片，并通过真实图片格式、文件大小和像素校验。
HTTP 200 本身不算成功。
仅 HTTP 502 最多重试两次，分别等待 0.5 秒、1 秒；同一次业务调用最多三次上游 POST。
其他状态、超时、断连、无图或无效图片都不重试，也不自动切换到其他生图通道。
`OPENAI_IMAGE_TIMEOUT_SECONDS` 是图片调用的总时限。失败或取消会释放本地生图占用，
不增加本地成功额度；上游是否计费以代理账单为准。

排查 GPT 图片失败时，可在日志中搜索 `event=gpt_image`。同一次图片调用通过 `attempt_id`
关联开始和结束记录，日志包含生成或编辑类型、模型、接口地址、耗时、HTTP 状态以及可用的
上游请求 ID；错误正文只保留脱敏后的摘要。普通对话的 `conversation_image_action_failed`
记录也会带相同 `attempt_id`。群内仅展示固定的简短错误说明。
若出现 401 或 403，应核对图片密钥权限；若出现模型分组 404，应核对代理是否为该 Key
开放了所选图片模型。`/models` 列表是否包含图片模型只能作为线索；只有真实
生成和编辑成功才能证明通道恢复。修改 `.env` 后需重启服务使配置生效。

GPT、NovelAI 和 Nai v5 共用每日成功生成额度和全局单任务锁；任一服务正在生图时，其他服务会
等待当前任务完成、失败或超时后才接受新任务。默认每个成员每天最多成功生成 100 张。

GPT 生图结果按接口返回的原始图片保存并上传 QQ，包括超过 2 MB 的图片；QQ 发送失败时
通过“查看图片”按钮展示同一份原图。
其他发往 QQ 的图片（包括网页找图和 NovelAI）会在上传前检查文件大小。
不超过 2 MB（2×1024×1024 字节）时保留原文件；超过时自动压缩为 JPEG，优先保持
原分辨率并降低编码质量，必要时等比例缩小，确保上传文件不超过 2 MB。透明区域合成
白色背景。压缩失败时显示图片交付失败提示，不上传超限文件。

图片压缩或尺寸处理失败、QQ 上传或发送失败时，只要仍有可读取且成功保存的图片，
失败提示就会附上“查看图片”按钮，使用与“查看完整输出”相同的链接按钮，电脑可在
浏览器中打开公网临时图片。QQ 交付失败使用已保存的处理后图片；本地处理失败使用原图，
这些非 GPT 图片不会把超限原图继续上传 QQ。同一条失败提示也保留可用的完整输出和本次提示词入口。
图片链接有效期由 `AIQQ_MEDIA_TTL_SECONDS` 控制，默认 15 分钟，过期后返回 404。
若没有有效图片或临时保存失败，只显示失败提示，不提供无效按钮。

OpenAI 图片工具参数说明见[官方 OpenAI 文档](https://platform.openai.com/docs/guides/image-generation)。

## NovelAI 文生图

收到非空的 `NovelAI生图`、`NovelAI快速生图` 或 `Nai v5 作图` 请求后，机器人会立即尝试
撤回用户的原消息，再发送一条接收通知。成功时同一条消息显示“已收到提示词，原消息已撤回。”，
不会另发撤回通知或重复的开始作画通知；旧版中文输入的转换提示也合并在这条消息中。
撤回要求机器人已设为群管理员、发送者是普通成员，且消息未超过两分钟。权限不足、超过时限或
接口失败时，接收通知会说明原消息未撤回，并继续现有作画流程，不会误报“已撤回”。
空的作画命令只返回用法提示，不撤回；提示词方案、画风设置和普通聊天也不触发此行为。

两套作画功能成功生成图片后，完成消息都会附上“查看本次提示词”按钮，复用临时回复页的
复制控件。页面按纯文本显示本次画面提示词，可一键复制，保留权重符号、中文和内部换行，
不包含保存的个人画风、服务自动添加的安全前缀或负面提示词。旧版中文输入显示转换后实际
选用的英文画面提示词；Nai v5 显示直接输入的画面描述。用户自己写在本次提示词里的内容
会保留，不通过文本替换删词。链接沿用回复页有效期，默认一小时。

“Nai v5 作图”面板命令支持直接输入中文或英文画面描述：

```text
@机器人 /Nai v5 作图 white cat, sitting by a window
@机器人 /Nai v5 作图 一只坐在窗边的白猫
```

也支持短命令 `@机器人 /Nai v5 提示词`（斜线可省略），与 `Nai v5 作图` 使用同一作图流程，
包括审核白名单、个人画风、撤回回执和本次提示词入口。`Nai v5 画风` 仍用于设置画风。

中文描述会原样传给 Nai v5 服务，不经过中文检测、翻译或标签转换。
生图时仅添加独立设置的个人 Nai v5 画风，并沿用图片审核、额度并发控制、开始通知和 QQ 图片交付。
新服务固定使用 `nai-diffusion-5-full`，保留既有尺寸、28 步和安全前缀；
请求固定单张，Seed 由 AiQQ 每次在 `1..4294967295` 范围内随机生成并明确发送，
关闭质量标签预设。服务文档虽然写着 `0` 表示随机，实际图片元数据却曾连续记录为 `0`，
因此项目不再依赖这个约定。日志中的 `event=nai_v5_generation_requested` 会记录本次发送的
Seed，便于核对。此命令只接受画面描述，不解析生成参数。

Nai v5 使用独立的固定负面提示词，保留成人内容防护，去掉 `loli`、`cleavage`、`shota`，
并加入指定的画质、解剖、瑕疵、文字水印及风格规避词。重复项合并，同词同时存在普通与
带权重版本时保留带权重版本；权重括号和 `3::anatomical nonsense::` 原样发送。
其中 `lineart`、`retro artstyle`、`depth of field`、`old` 等也会抑制相应画风或人物特征。
完整内容定义在 `src/aiqq/services/images/novelai.py` 的 `NAI_V5_NEGATIVE_PROMPT`。


可以通过面板中的“NovelAI画风”和“Nai v5 画风”分别保存两套个人英文画风提示词：

```text
@机器人 /NovelAI画风 watercolor, soft lighting
@机器人 /NovelAI生图 white cat
@机器人 /Nai v5 画风 pixel art, soft lighting
@机器人 /Nai v5 作图 一只坐在窗边的白猫
```

原版 NovelAI 会自动使用 `watercolor, soft lighting, white cat`；Nai v5 则使用
`pixel art, soft lighting, 一只坐在窗边的白猫`，合并后再审核。
两套画风分别保存、读取和清除，互不影响。原有画风只保留在原版 NovelAI 中，
Nai v5 初始没有画风，需要通过“Nai v5 画风”单独设置。
手动输入和点击“使用方案”都生效；生成提示词方案时不提前拼接画风，生图时读取最新设置。
每次输入新画风会覆盖并启用对应版本的设置。直接发送 `@机器人 /NovelAI画风` 或
`@机器人 /Nai v5 画风`（后面不写内容）只会清除对应版本的画风。
画风按 QQ 提供的发送者标识保存到数据库，同一标识在不同群中共用设置，重启后仍保留；
不会影响其他用户或 GPT 生图。设置或清除画风不调用生图服务，也不消耗图片额度。
画风须使用英文提示词，权重括号和内部换行会保留；不合格的输入不会覆盖已有设置。

需要先把中文或自然语言画面描述整理成 NovelAI 提示词时，可发送：

```text
@机器人 /NovelAI提示词 一位站在樱花树下的白发少女
```

AI 会根据当前画面描述，在新的临时 Codex thread 中返回三套各有侧重的英文提示词。
生成和修改方案只整理主体、外观、服装、动作、构图、场景与光照；规则禁止加入
`best quality`、`masterpiece` 等质量词、画面渲染风格、绘画媒介及画师标签，输入或旧方案
含有这些内容时也应排除。个人画风通过“NovelAI画风”单独设置，实际生图时才添加。
生成和修改都会先由模型提取最多 8 个英文画面概念，再通过已配置 NovelAI MCP 的
`suggest_tags` 查询 Danbooru 标签，最后根据查询结果编写三套方案。每个概念最多提供
8 个候选，含标签分类和使用次数；先考虑与原描述的相关性，再参考使用次数。
查询结果中的画师和元数据分类会被过滤。查询成功但没有匹配时可用简短英文描述表达原意；
查询失败或超时会明确提示“Danbooru 标签查询失败，请稍后重试。”，不会跳过查询继续生成。
这条流程使用专门的标签接口，不开启通用 Web Search；查询不调用生图服务，也不消耗图片额度。
三个绿色标识的“使用方案”按钮各自独占一行，点击后会把完整的
`NovelAI生图 <提示词>` 填入输入框，但不会自动发送。点击“修改提示词”后，可以在
自动填入的命令后继续写要求，例如“方案2改成夜景，并使用半身构图”；每次修改会返回
新的三套方案。修改会话与当前群和用户绑定，保存在 SQLite 中，15 分钟后失效。

提示词生成和每次修改都会使用新的临时 Codex thread；修改时通过当前群成员专属、15 分钟
有效的 SQLite 会话取得原方案。整理和修改提示词只调用 AI，不调用 NovelAI，也不占用每日
图片额度；只有 `NovelAI生图` 或 `NovelAI快速生图` 实际成功生成图片时才计入额度。

希望省略选择方案步骤时，可以直接发送快速生图指令（不在 QQ 指令面板中显示）：

```text
@机器人 /NovelAI快速生图 一位站在樱花树下的白发少女
```

该指令执行与“NovelAI提示词”相同的审核、Danbooru 标签查询和三套英文提示词编写，随后
固定采用第一套方案直接进入现有 NovelAI 生图流程。中间不会发送提示词方案或按钮，也不会
保存 15 分钟修改会话；个人画风、生图审核、额度、开始作画通知和错误处理均与
`NovelAI生图` 相同。提示词编写失败时不会调用生图服务或占用图片额度。

指令面板中的“NovelAI生图”会把 `/NovelAI生图` 填入输入框，用户只需在后面
输入提示词。机器人同时兼容带斜线与不带斜线的命令：

```text
@机器人 /NovelAI生图 1girl, silver hair, red eyes, night city
```

该命令不会调用普通 GPT 对话。输入包含汉字时，自动走与“NovelAI快速生图”相同的流程：
审核画面描述、查询 Danbooru 标签、编写三套英文提示词，并选用第一套直接生图；不会显示
中间方案或修改按钮，也不会创建修改会话。成图前的完成消息会附上“查看本次提示词”按钮，
可打开临时页面查看并复制选用的英文画面提示词，不包含已启用的个人画风。
英文提示词继续直接进入生图审核；审核会通过独立的临时 Codex thread 检查成人内容、
画面有效性及是否包含中文。英文提示词审核未通过时，
机器人会给出一条保持原意的英文提示词建议，并在回复中直接显示绿色标识的“使用建议”按钮。
腾讯 QQ 原生键盘只提供灰色与蓝色线框，因此该按钮使用绿色标识和灰色线框，与菜单中的
蓝色功能按钮区分。按钮会把 `NovelAI生图 <建议提示词>` 填入输入框，但不会自动发送。
统一审核不通过或审核服务异常时也不会调用 NovelAI。任何提示词前置检查发生拦截时，
机器人都会显示具体的拦截原因并给出一条安全英文建议；当前回复中的“使用建议”按钮会直接
填入该建议。英文输入整体只作为
`prompt`，含汉字的输入作为画面描述；项目不会解析模型、尺寸、Seed、负面提示词或其他生成参数。

生图审核允许非色情语境下的正常露肤、泳装、运动服、赤足以及手部、腿部和足部特写；
不会仅因 `barefoot`、`foot focus` 或 `foot close-up` 等单一标签判定为恋物内容。只有出现
明确裸体或私密部位暴露、色情行为、性暗示、恋物意图或未成年人性化内容时才会拦截。

管理员可用 `AIQQ_IMAGE_AUDIT_WHITELIST` 配置作图审核白名单，填写实际 QQ
`member_openid`，以英文逗号分隔，默认为空。白名单账号使用 `NovelAI生图`、
`NovelAI快速生图`、`Nai v5 作图`（或短命令 `Nai v5`）和 `GPT生图` 时，跳过机器人本地的安全与画面有效性
审核；旧版中文作图转换前、转换后的两层审核都会跳过。名单按发送账号匹配，跨群生效，
与 `AIQQ_NAI_V5_WHITELIST` 的额度豁免独立；修改 `.env` 后重启服务生效。
普通聊天和独立的 NovelAI 提示词方案功能沿用各自的审核流程。此设置只控制机器人本地
审核，生图服务与 QQ 自身的限制仍然生效。

白名单账号的 NovelAI/Nai v5 构图方向不再调用审核模型，而是从本次画面提示词本地识别：
`lying`、`reclining` 或“躺”“侧卧”等明确躺姿用横图，`full body`、`full_body` 或“全身”
用竖图，其余用方图；躺姿优先，个人画风中的词不影响此判断。

当前生成配置固定为 `v4.5-full`、28 步和单张图片。非白名单账号由审核同时判断构图方向：默认使用
`1024x1024` 方图，明确的全身构图使用 `832x1216` 竖图，躺姿使用 `1216x832` 横图；
同时出现全身和躺姿意图时以横图优先。生成请求会添加
`rating:general, safe, sfw` 以及仅包含成人内容防护的固定负面提示词。原版不会自动
追加画质、构图、肢体或瑕疵规避标签，NovelAI 的官方质量标签开关也保持关闭；多样性
增强保持开启。MCP 已公开 `steps` 参数，项目会在每次生成时显式传入 28。
`CFG Rescale` 固定为 `0.5`。

普通对话生图、`/GPT生图`、NovelAI 与普通用户的 Nai v5 生图共用每日额度，
默认同一群内每个成员每天最多成功生成 100 张；Nai v5 另外按成员跨群限制每天 10 张。
白名单仅在 Nai v5 生图时绕过所有每日额度。机器人全局同一时间只处理一项生图任务；
上一项生成完成、失败或超时后，才会接受下一项。GPT 文生图和改图收到 HTTP 502 时，
分别等待 0.5 秒、1 秒，最多自动重试两次；同一次任务最多发出三次请求，成功仅计一次
本地额度。其他 HTTP 错误（包括 404、429）、超时、连接故障及无效图片响应不自动重试。
重试写入 `gpt_image_retry` 日志，可通过同一个 `attempt_id` 关联开始、重试和结束记录。
生成超时后不会自动重试，以免产生重复费用。

部署到本机服务后，可以通过下面的地址检查进程、QQ 网关和 AI 后端状态：

```text
https://www.firesoul.cn/aiqq/health
```

`qq_gateway.connected` 为 `false` 时接口返回 HTTP 503，并记录最近断线时间、关闭码及累计
重连次数。SDK 通常会在约 5 秒内自动恢复；连续断线超过
`AIQQ_GATEWAY_RESTART_TIMEOUT_SECONDS`（默认 90 秒）时，机器人进程会退出并由 systemd
自动重启。`ai_backend=codex_sdk` 表示模型回合由机器人进程通过 Python SDK 启动，与管理员
当前打开的 Codex 窗口相互独立。

## 常见问题

- 提示凭据错误：确认 `AppID` 与 `Secret` 属于同一个机器人，Secret 重置后要同步更新 `.env`。
- 收不到消息：确认机器人已加入群聊，并已开启群聊消息事件权限。
- 提示 AI 尚未配置：在 `.env` 中填写 `OPENAI_API_KEY` 后重启服务。
- AI 返回接口错误：确认密钥与 `OPENAI_BASE_URL` 属于同一个服务，执行 `uv sync --locked` 和 `npm ci`，
  并检查 `OPENAI_MODEL` 与 `AIQQ_CODEX_CLI`。
- 群历史没有进入回答：确认群管理员已开启“接收所有消息”，并检查群历史统计日志。
- NovelAI 不可用：检查 MCP 地址、Token、外网连接和服务端 `generate_image` 工具。
- 图片无法显示：机器人会先让 QQ 从 `AIQQ_PUBLIC_BASE_URL` 拉取临时图片，再使用 QQ 富媒体消息发送；请确认该公网地址可访问，并将 `/aiqq/media/` 反向代理到本服务的 `/media/`。
- 完整原文打不开：确认 `/aiqq/reply/` 已反向代理到本服务的 `/reply/`，并检查随机链接是否已超过 `AIQQ_REPLY_TTL_SECONDS`。
- 关闭终端后离线：本机测试阶段这是正常现象；正式使用时需部署到持续运行的服务器。
